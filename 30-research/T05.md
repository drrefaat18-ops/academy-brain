# T05 — microbit.org unit pedagogy + kids-track rubric alignment

Merged union of 3 lanes, no adjudication. Applies to L1-s1..s6 (all).

## hermes

- The unit structures every lesson on a recurring Think → Create → Evaluate → Extend → Share arc, reproduced verbatim in the L1-s2..s6 decks per R0 provenance delta. — https://microbit.org/teach/lessons/
- For a young-kids track, Think should open with one concrete physical artefact (name badge, beating heart on LED matrix) so abstract code anchors to a tangible object (Merrill's First Principles). — MID:first-principles
- Reduce extraneous cognitive load: one idea per slide, chunk Create into small build steps (Sweller's CLT). — MID:cognitive-load-theory
- Age-appropriate pacing should shorten reflective Evaluate/Extend segments, interleave frequent hands-on interaction rather than long teacher-talk (UDL). — MID:udl
- Share phase for young kids should have them physically show their artefact to peers rather than written reflection (Self-Determination Theory: relatedness/competence). — MID:self-determination-theory
- All six sessions currently omit upstream differentiated support/challenge and assessment guidance — kids-track adaptation must re-insert age-appropriate differentiation and success criteria into Evaluate/Extend. — https://microbit.org/teach/lessons/

## codex

- Lessons use Think, Create, Evaluate, Extend, Share; Create supports code examination, building, tutorials, coding-video scaffolds. — https://microbit.org/projects/make-it-code-it/beating-heart/
- For young children, keep the lesson cycle but centre each session on one observable input-to-output idea. — MID:concrete-operational-learning
- Use Think to elicit a short prediction about a familiar physical action before introducing matching code, reducing novice cognitive load. — MID:cognitive-load-theory
- Present one new concept/action per slide, large visual + brief teacher demo, before Create reproduction. — MID:segmenting-principle
- Make Evaluate a brief show-and-tell/teacher observation against a visible success criterion — provenance identifies missing formal assessment in several sessions. — https://microbit.org/teach/lessons/step-counter/
- Offer Extend as optional, clearly bounded, after the core build works (UDL). — MID:universal-design-for-learning
- End Share with pair demonstration + simple sentence stem describing what the program does. — https://microbit.org/projects/make-it-code-it/beating-heart/

## opencode

- The "First lessons" unit structures every project around THINK–CREATE–EVALUATE–EXTEND–SHARE. — https://microbit.thinkific.com/courses/first-lessons-with-makecode-and-the-micro-bit
- Unit explicitly lists "Evaluate"/"evaluation"/"modifying"/"prototyping" as skills — young-kids track must keep an explicit Evaluate and Share stage rather than drop it. — https://microbit.org/teach/lessons/first-lessons-with-makecode-and-the-microbit/
- Youngest-pitched micro:bit units (ages 7-9) use 2-5 short lessons each producing one concrete physical artefact — L1-s1..s6 should pace by one tangible make per lesson. — https://microbit.org/teach/lessons/
- Best practice favours unplugged, hands-on kinesthetic activities priming abstract concepts before screen-coding; L1-s1 should open screen-free. — L1-s1,s2 — MID:unplugged-before-screens
- Young children learn best with one idea per slide, minimal clutter. — MID:one-idea-per-slide
- Concrete physical examples beat abstract explanation for ages 6-8 — tie each coding idea to a real object/action the child can see and touch. — MID:concrete-physical-examples
- Frame debugging as a "detective game," celebrate finding/fixing bugs — maps onto Evaluate/Extend, suits young kids' resilience-building. — L1-s3,s4,s5,s6 — MID:debugging-as-detective-game
