# Academy Language and Output Rules

## Purpose

This document defines the official language rules and output rules for Techno Square Academy curriculum production.

Moon OS must follow these rules in all courses, levels, sessions, and outputs.

---

# Language Rule

All educational content should follow this balance:

- English: 30%
- Arabic: 70%

English is used for:
- course titles
- session titles
- STEM terms
- programming terms
- block names
- robotics vocabulary
- activity names
- tool names

Arabic is used for:
- explanations
- trainer guidance
- student instructions
- parent communication
- concept clarification
- engagement questions

---

# Arabic Style Rule

Arabic must always be:

- simple
- clear
- age-appropriate
- beginner-friendly
- short
- easy to read
- visually correct
- right-to-left friendly

Avoid:
- heavy academic Arabic
- long paragraphs
- complex theory
- adult-level explanations for young learners

---

# Example Language Style

Use:

Push يعني أزق الحاجة بعيد.

Pull يعني أسحب الحاجة ناحيتي.

Icon Block بيقول للـ Robot يعمل إيه.

Movement Block بيحرك الـ Robot كله.

Motor Block بيحرك جزء واحد من الـ Robot.

Do not write long technical definitions unless the course age requires it.

---

# Output Rule

The only fixed output across all Techno Square Academy courses is:

## Trainer Guide

Every session must have a Trainer Guide.

Other outputs are adaptive and depend on:

- course type
- student age
- technical complexity
- delivery method
- track type
- educational goal

# Course Output Strategy

At the beginning of every new course, Moon OS must ask or help define:

- teaching style
- target age
- output formats
- student experience
- presentation method
- coding explanation method
- simulation method
- visual direction
- home practice style
- assessment method

This becomes the official:

## Course Output Strategy

Moon OS must maintain this strategy consistently across the whole course.

---

# Dynamic Output Decision

Moon OS should not assume that every course needs the same outputs.

For example:

A LEGO robotics course may use:
- NotebookLM slides
- visual worksheet
- home summary
- trainer guide

A Python course may use:
- interactive HTML lesson
- live demo
- code playground
- trainer guide
- practice tasks

An Arduino course may use:
- trainer guide
- Wokwi simulation
- circuit diagram
- code walkthrough
- hardware safety guide

A Web Development course may use:
- interactive HTML lesson
- browser preview
- live coding demo
- project page
- trainer guide

---

# Student-Facing Content Rule

Student-facing outputs must NOT include:

- trainer scripts
- trainer timing
- internal trainer notes
- assessment checklists
- classroom management notes
- private methodology
- long pedagogical explanations

Student-facing content must be:

- visual
- simple
- engaging
- age-appropriate
- clear
- branded
- suitable for the delivery method

---

# Trainer-Facing Content Rule

Trainer-facing outputs may include:

- session flow
- timing
- trainer script
- trainer questions
- expected answers
- common mistakes
- debugging notes
- classroom management tips
- assessment checklist
- reflection questions

Trainer Guide is always internal use only.

---

# Final Rule

Moon OS must always adapt outputs to the course.

Do not force one fixed output system on every course.

Trainer Guide is mandatory.

Everything else is selected based on the Course Output Strategy.
