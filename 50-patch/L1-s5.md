## slide-11 (evaluate demo check)
- severity: medium
- type: assessment
- lanes: [codex, opencode]
- problem: Evaluate questions are open reflective prompts with no observable success criteria, so a working device alone can't distinguish understanding from copied code.
- fix: Add a brief teacher-observed demo: learner varies light, shows the expected LED response, and explains the if/else decision.
- cites: ["https://microbit.org/teach/lessons/step-counter/", "MID:formative-assessment-lightweight-kids"]

## slide-12 (threshold comparison, predict-before-swap)
- severity: medium
- type: technical
- lanes: [codex, hermes]
- problem: Inviting learners to swap `<` for `>` without requiring a prediction/test risks cementing the misconception that comparison symbols are interchangeable, and doesn't flag that the swap reverses the nightlight (LEDs on in bright light, not dark).
- fix: Require the extension to predict and verify the reversed outcome, explicitly framing `>` as intentionally inverting behaviour relative to the threshold.
- cites: ["https://makecode.microbit.org/lessons/blocks-conditions", "MID:makecode-threshold-comparison"]

## slide-12 (bounded extend)
- severity: medium
- type: differentiation
- lanes: [opencode]
- problem: The single Extend option (invert the comparison) functions as an inversion of the core task rather than a bounded, scaffolded challenge for early finishers.
- fix: Add a bounded challenge (e.g. different icons for bright/dark) as the stretch, keeping the core if/then success criterion intact.
- cites: ["MID:universal-design-for-learning", "https://microbit.org/projects/make-it-code-it/beating-heart/"]

## slide-3 (concrete anchor for light sensor)
- severity: medium
- type: pedagogy
- lanes: [opencode]
- problem: Light sensor is introduced only via an external video; the concrete 0-255 range fact is delayed to optional slide-4 notes, weakening the tangible anchor for young learners.
- fix: Surface the 0 (dark) to 255 (bright) light-level range directly on the sensor-introduction slide.
- cites: ["MID:concrete-physical-examples", "MID:segmenting-principle"]

## slide-4 (objective tiering)
- severity: medium
- type: pedagogy
- lanes: [hermes]
- problem: Three learning objectives are presented flat on one slide with no tiering, raising cognitive load for a young-kids track.
- fix: Split into one-idea-per-slide or tiered Mild/Medium/Spicy objectives so novices anchor on the core outcome first.
- cites: ["MID:cognitive-load-theory"]
