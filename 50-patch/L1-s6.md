# 50-patch — L1-s6 (Rock-Paper-Scissors)

## slide-10 (evaluate success criteria)
- severity: high
- type: assessment
- lanes: [codex, opencode, hermes]
- problem: Evaluate is broad reflection questions with no observable success criteria or evidence-collection method for the shake/random/three-outcome objectives (R0 `missing: assessment`).
- fix: Insert a lightweight two-person demo check (one shakes, partner predicts and names the three possible outcomes and the choice logic) or oral exit-ticket.
- cites: ["https://microbit.org/teach/lessons/rock-paper-scissors/", "MID:formative-assessment-lightweight-kids"]

## differentiation (support tier)
- severity: high
- type: differentiation
- lanes: [codex, opencode, hermes]
- problem: Build/Extend offers only stretch tasks with no paired support tier for struggling learners (R0 `missing: differentiation`).
- fix: Add a support option — pre-built remix/starter or single-branch if/then skeleton — alongside the existing stretch challenge (e.g. two-microbit radio play, scoring) so all learners reach the shake-and-random core.
- cites: ["https://microbit.org/teach/lessons/rock-paper-scissors/", "MID:principle-low-floor-high-ceiling"]

## answer_key
- severity: high
- type: other
- lanes: [codex, hermes]
- problem: NON-NEGOTIABLE (rubric §5, T03-documented) — upstream RPS answer-key/success-criteria was dropped; slide-5/12 narrate logic but define no canonical correct/incorrect checks.
- fix: Author a short answer key: shake → random 1-3 → show rock/paper/scissors mapping; flag common mistakes (fixed/non-random outcome, missing shake handler, incomplete three-way mapping) while accepting different icon designs.
- cites: ["https://microbit.org/teach/lessons/rock-paper-scissors/", "MID:L1-s6"]

## block-showIcon (no built-in RPS icon)
- severity: high
- type: technical
- lanes: [opencode]
- problem: There is no built-in rock/paper/scissors `show icon`, so a deck instructing learners to use `show icon` for these shapes will silently fail to display the intended shape.
- fix: Require three custom `show leds` patterns (one per throw) instead of `show icon`.
- cites: ["https://makecode.microbit.org/reference/basic/show-leds"]

## slide-2 (one-device "plays itself" misconception)
- severity: high
- type: pedagogy
- lanes: [opencode]
- problem: Lesson shows shake→random→icon without clarifying that real Rock-Paper-Scissors needs two players/comparison, so learners may think the micro:bit "plays" the game by itself.
- fix: Add a concrete discussion that the device acts as a random referee/throw-picker (one player's choice), or introduce two-microbit radio play for a genuine two-player version.
- cites: ["MID:concrete-to-abstract", "https://makecode.microbit.org/reference/input/on-gesture"]

## random-range inclusivity
- severity: medium
- type: technical
- lanes: [codex, opencode]
- problem: The deck doesn't make explicit that the random-number block must produce only inclusive values 1-3 (or 0-2) each shake, risking beginner confusion between exclusive `Math.random(3)` and inclusive `pick random` — an off-by-one icon mismatch.
- fix: State the required block and range explicitly (`pick random 1 to 3`, inclusive), and map each of the three values to exactly one icon before the else branch.
- cites: ["https://makecode.microbit.org/reference/math/randint", "https://makecode.microbit.org/reference/math/random"]

## on-gesture-Shake (multi-fire on one shake)
- severity: medium
- type: technical
- lanes: [opencode]
- problem: A single physical shake can fire the gesture handler multiple times rapidly, cycling through several icons before the learner sees a stable result.
- fix: Add a short `pause` or a state flag so one shake shows exactly one stable throw.
- cites: ["https://makecode.microbit.org/reference/input/on-gesture"]

## slide-5 (one-idea-per-slide chunking)
- severity: medium
- type: pedagogy
- lanes: [hermes]
- problem: "Examine the code" slide bundles four distinct concepts (gesture trigger, random variable, conditional logic, three-way icon mapping) on one slide, conflicting with one-idea-per-slide/chunking guidance for young learners.
- fix: Split the code examination into separate mini-steps (trigger, variable, condition, icons), one concept per slide, before the build.
- cites: ["MID:one-idea-per-slide", "MID:cognitive-load-theory"]

## slide-11 (tally-chart predict-and-compare)
- severity: medium
- type: assessment
- lanes: [codex]
- problem: The tally-chart extension measures game results but doesn't prompt learners to predict, interpret, or compare outcomes, so it doesn't assess understanding of randomness/fairness.
- fix: Ask learners to predict whether the three outcomes will be similarly frequent, tally a fixed number of trials, and explain whether the evidence changes their fairness claim.
- cites: ["https://microbit.org/teach/lessons/rock-paper-scissors/", "MID:observable-behavior-and-structure"]

## slide-3 (concrete shake-and-predict opening)
- severity: medium
- type: pedagogy
- lanes: [codex]
- problem: The opening asks novices to recall inputs, random numbers, variables, and logic in one discussion before any concrete shake-to-icon prediction or demonstration.
- fix: Begin with a short physical shake-and-predict demonstration, then introduce each code concept only when it's encountered in the build.
- cites: ["MID:cognitive-load-theory", "MID:concrete-operational-learning"]
