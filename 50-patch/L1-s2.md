## on-start-vs-forever (static heart misconception)
- severity: high
- type: technical
- lanes: [opencode, hermes]
- problem: Deck explains `forever` as an infinite loop but never warns that placing the heart animation in `on start` instead runs it once, producing a static (non-beating) heart — a documented key mistake for this task.
- fix: Add explicit contrast: `on start` = single run, `forever` = repeats in background; a single `show icon` in `forever` still shows a static heart because the image persists until the next `show icon` — two frames + pauses are required for a visible beat.
- cites: ["MID:makecode-animation-pacing", "https://makecode.microbit.org/reference/basic/forever", "MID:state-persistence"]

## slide-5 (show-icon default interval)
- severity: medium
- type: technical
- lanes: [codex, opencode, hermes]
- problem: Teacher notes model frame timing purely via the two `pause` blocks, but `show icon` also carries its own default ~600ms display interval — never mentioned — so learners may misjudge total frame duration when tuning pauses.
- fix: Note that each `show icon` holds its image for a default interval and `pause` adds to it; also clarify `pause` units (1000ms = 1 second) so learners don't read "1000" as "1 beat."
- cites: ["https://makecode.microbit.org/reference/basic/show-icon", "https://makecode.microbit.org/reference/basic/pause"]

## slide-3 (two-frame animation misconception)
- severity: high
- type: pedagogy
- lanes: [opencode]
- problem: Lessons often imply one `show leds`/`show icon` block "makes the heart beat," leaving learners confused when nothing animates.
- fix: Explicitly teach that animation needs at least two different frames shown in sequence with pauses between them before learners build.
- cites: ["https://makecode.microbit.org/projects/beating-heart", "MID:animation-requires-two-frames"]

## slide-5 (compare non-looped vs looped)
- severity: medium
- type: pedagogy
- lanes: [codex]
- problem: Lesson claims loops make code "compact and readable" but gives no side-by-side non-looped sequence for learners to compare against the four-block `forever` solution.
- fix: Add a brief prediction-and-compare prompt contrasting repeated copies of the two frames with the looped sequence.
- cites: ["MID:cognitive-load-theory", "https://microbit.org/projects/make-it-code-it/beating-heart/"]
